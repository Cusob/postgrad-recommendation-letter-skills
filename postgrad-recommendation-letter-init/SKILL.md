# 保研自荐信初始化

这是入口 Skill，只负责建立和维护使用者的简历资料、自荐信底稿和底稿结构契约。它不调研导师、不下载或精读论文、不改写某位导师的信。完成初始化后，使用 `$postgrad-recommendation-letter-run` 执行具体导师任务。

## 文件边界

Skill 安装目录及其中的 `SKILL.md`、`references`、`agents`、`tools` 和 `assets` 是只读可复用资产。用户简历、用户底稿、状态文件、结构快照和任务产物只能写入当前工作区，不能因为更新简历或底稿而修改 Skill 文件。

## 首次调用

如果当前工作区没有可用的 `.postgrad-recommendation-letter/profile.json`，主动索取：

> 请上传个人简历（必需，PDF/DOCX 均可）。如果有希望沿用版式和写作风格的自荐信模板，也可以一并上传，但模板是可选的；不上传时使用通用默认模板。

简历是初始化的必需材料。读取简历后整理姓名、教育、成绩、推免资格、科研、竞赛、奖项、技能和申请偏好；每项事实保留来源，示例值、星号和疑似模板占位符标为待确认，不能直接进入正式信件。

初始化后，`profile.json` 中的 `resume.path` 和 `resume.sha256` 是简历的唯一权威绑定。执行和更新时必须读取并验证这条精确路径；不能按文件名、当前目录、搜索结果或用户历史消息寻找、替换或猜测另一份同名简历。相对路径只相对于当前工作区解析。

用户上传模板时，将完整 DOCX 登记为后续实际改写底稿，保留其版式、段落组织和语气偏好。模板中的姓名、学校、成绩、旧导师、旧论文和旧研究方向不自动当作用户事实。用户不上传模板时，登记内置默认 DOCX。

登记底稿后必须建立结构契约。优先调用执行 Skill 附带的 `tools/docx_workbench.py snapshot`，或者使用等价的 DOCX 检查方法，保存与底稿文件哈希绑定的快照。快照至少包括：

- 正文、表格、页眉页脚和 section 的数量与位置；
- 页边距、段落样式、对齐、缩进、行距和署名位置；
- 每个段落的文本、占位符、run 数和 run 样式摘要；
- 图片、文本框、超链接等可识别对象的摘要；
- 模型根据段落文本、占位符、位置和上下文判断的段落职责映射及判断依据。

段落职责映射是辅助判断，不是事实。无法确定时标为低置信度，执行时重新审查，不能按段落序号强行套用默认模板。

## 已初始化时

读取状态并简要展示当前简历、底稿哈希和结构契约状态，询问用户是继续使用、更新简历、还是更换底稿。用户提供“满意稿”“以后沿用”等明确指令和 DOCX 时，将该文件登记为新的底稿，重新生成结构快照；不要把其中的导师事实写入个人资料。普通的局部反馈不自动改变长期底稿。

如果读取到旧 schema 的有效状态（例如 v2 的 `schema_version: 1`），执行向前迁移：保留现有简历路径、个人事实、来源、底稿路径和哈希；不要要求用户重新上传已可读取的简历。对已有 DOCX 底稿重新生成 v3 结构快照和段落职责映射，再将状态升级为 schema 3。迁移中遇到缺失或冲突字段时保留原始信息并标注待确认，不得静默清空。

如果底稿文件已经被用户在外部修改但没有明确要求更新模板，先提示底稿哈希或快照不一致，请用户确认是继续使用该文件还是将其登记为新底稿。

如果简历精确登记路径存在且哈希匹配，即使其他目录存在同名或更新的简历，也继续使用登记路径。只有用户明确确认“更新简历”并提供新的文件时，才重新读取个人事实、更新 `resume.path`、`resume.sha256` 和相关 profile 内容。底稿更新不触发简历更新。

发生简历状态异常时，报告必须区分：

- `registered_file_missing`：登记的精确路径不存在；
- `registered_file_changed`：登记的精确路径存在，但文件哈希发生变化；
- 路径冲突：发现其他同名文件，但登记路径本身有效。路径冲突不是简历变更，不得阻断。

优先使用执行 Skill 附带的 `tools/resume_workbench.py profile.json` 做只读校验。该工具不会扫描替代文件，也不会修改状态。

## 状态接口

状态文件固定为当前工作区的 `.postgrad-recommendation-letter/profile.json`，结构见 [profile-schema.md](references/profile-schema.md)。入口写入，执行 Skill 只读。

初始化完成后告知用户：

> 初始化完成。现在使用 `$postgrad-recommendation-letter-run`，指定学校、学院、导师和可选主页链接，即可开始完整调研、论文精读、自荐信改写与 DOCX 交付。

示例：

`使用 $postgrad-recommendation-letter-run，调研【学校】【学院】的【导师】老师；官网主页：【可选 URL】。完成完整流程并输出 DOCX。`

## 读取默认模板

无用户模板时使用 `assets/default-letter-template.docx`，通用段落结构见 [default-template.md](references/default-template.md)。

默认模板也必须生成结构契约。默认模板和用户模板使用相同的保真和 QA 规则，不因为是内置文件就允许重新生成或丢失局部样式。
