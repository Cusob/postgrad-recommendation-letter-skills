# 保研自荐信执行

这是执行 skill。它读取 `$postgrad-recommendation-letter-init` 建立的 `.postgrad-recommendation-letter/profile.json`，然后为一所学校和一位导师完成完整任务。它不是僵硬的检索脚本：阶段顺序明确，但搜索、浏览、下载和取舍由模型根据当前证据自主判断。

## 输入

用户需要提供学校和导师姓名；学院、申请学位、研究方向和导师主页链接可一并提供。主页链接只是定位线索和官方证据起点，即使提供了主页，也必须继续做多方面调研。

未指定停止点时，执行完整流程并尝试交付研究报告、完整自荐信正文和目标导师 DOCX。也可指定“只做导师调研”“只读论文/准备面试”或“只改写正文”。

## 少量硬约束

- 先读取并验证入口状态和简历；状态无效时请用户调用 `$postgrad-recommendation-letter-init`。
- 简历和用户最新确认是个人事实依据；不得编造个人经历、导师事实、作者关系或论文细节。
- 必须真正调研导师，不能只把主页关键词改写进信件。
- 只有下载到并实际读取本地 PDF 的论文，才能称为“已阅读”或“精读”。摘要、搜索片段和元数据不能冒充全文阅读。
- 上传模板或满意稿时，使用完整 DOCX 作为底稿；以简历为准审查和修改全部不匹配内容，不只替换占位符。
- 用户要求 DOCX 时生成新文件，不覆盖原简历、原底稿或默认模板，并做基本事实和可打开性检查。

## 推荐工作顺序

1. 读取初始化状态，确认个人资料、底稿和本次任务信息。
2. 调研导师身份、单位、职称、研究方向、研究路径和公开成果。
3. 先理解导师研究主线，再选择通常两篇最有代表性的论文：一篇体现核心主线，一篇体现阶段变化、当前方向或真实的学生连接。代表性和研究价值优先于关键词匹配与下载便利，但不要求机械评分。
4. 自主追踪并获取选定论文全文。先检查工作区已有文件；使用当前可用的 Codex 搜索、浏览、页面访问和文件下载能力，沿着有价值的线索继续查找。实际打开链接、保存 PDF、核对文件和论文信息，然后读取本地 PDF。
5. 按 [paper-reading.md](references/paper-reading.md) 精读所有最终选定论文。
6. 按 [template-adaptation.md](references/template-adaptation.md) 阅读完整底稿、以简历为准改写正文并生成目标 DOCX。
7. 按 [docx-qa.md](references/docx-qa.md) 做高价值最终检查，输出结果和路径。

这是一条推荐顺序，不是固定搜索渠道清单。遇到一个网站、域名或下载方式失败时，改变检索路径，继续追踪题名、DOI、作者、机构、论文列表和全文入口；不要机械重复同一个失败请求，也不要因为某个工具或网站不可用就结束。

## 论文获取与停止

论文全文获取的目标是找到可实际读取的本地 PDF。可以使用正式出版 PDF、作者版本、accepted manuscript、机构仓储、实验室页面、预印本或其他能够核验题名和作者的可靠全文版本。不要把固定渠道列表当成完成条件。

默认争取两篇论文。某篇代表作暂时不可得时，继续自主寻找新入口；必要时从候选池中换成下一篇仍然有代表性的论文。实际精读一篇也可以，只要它确实代表导师研究；不能为了完成数量改用边缘论文。

只有在确实无法获得并读取足够的代表性论文全文时，才停止论文特定写作。此时不生成虚假的导师专属自荐信或 DOCX，报告已经完成的导师调研、论文候选、已尝试路径和可继续使用的来源。不要把某个局部失败写成整个任务的常规 `BLOCKED` 状态。

如果核心个人资料仍是占位符或待确认，导师调研和论文工作可以继续；生成正式正文或 DOCX 前，要求用户确认姓名、学校、专业、成绩等必要字段。

## 任务记录与恢复

在当前工作区保存轻量任务目录，至少包含研究报告、论文候选与来源、`papers/`、必要的 `sources/` 和一份简短恢复说明。重新执行时先阅读已有产物，复用已完成的导师调研和有效 PDF，只继续未完成部分；不要因为旧记录中出现一次失败就直接停止。

## 输出

完整成功时输出：导师研究报告、代表性论文选择说明、逐篇论文精读、自荐信正文、目标导师 DOCX 和简短 QA 结果。正文必须使用实际读取的论文内容，语言真诚、克制、具体，不把学生经历夸大成导师论文方法的既有经验。
