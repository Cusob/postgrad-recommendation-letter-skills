# 保研自荐信执行

这是执行 Skill。它读取 `$postgrad-recommendation-letter-init` 建立的 `.postgrad-recommendation-letter/profile.json`，然后为一所学校和一位导师完成导师调研、代表性论文研究、自荐信改写和 DOCX 交付。

它是目标驱动的研究与写作流程，不是固定搜索脚本：阶段职责明确，搜索、浏览、下载和取舍由模型根据当前证据自主判断。工具只处理 DOCX 的机械操作，不能替代模型判断导师身份、论文代表性或正文内容。

## 输入

用户需要提供学校和导师姓名；学院、申请学位、目标方向和导师主页链接可一并提供。主页链接是定位和身份核验线索，不是唯一来源。即使用户提供主页，也要继续进行多方面调研。

未指定停止点时执行完整流程，尝试交付研究报告、论文精读、完整自荐信正文和目标导师 DOCX。用户也可以指定“只做导师调研”“只读论文/准备面试”或“只改写正文”。

## 不可逾越的事实边界

- 先读取并验证初始化状态、简历、底稿路径、底稿哈希和底稿契约；状态失效时请用户调用 `$postgrad-recommendation-letter-init`。
- 简历和用户最新明确确认是个人事实依据。底稿中的旧个人信息只是待审查内容，不能自动当作事实。
- 不能编造个人经历、导师身份、导师作者关系、论文方法、实验结果或联系方式。
- 只有实际下载并读取本地 PDF 的论文，才能在正文中称为“阅读/精读了该论文”，并据此写具体方法、实验和局限。
- 可靠 HTML/XML 全文、摘要和元数据可以进入证据账本，但必须保留证据等级，不能混称为 PDF 精读。
- 上传模板或满意稿是完整底稿，不是占位符集合。以其实际结构为基础，以简历为准审查全部普通正文和占位符。
- 生成目标文件时复制底稿，不覆盖原简历、原底稿或默认模板。

## 完整工作流

### 1. 读取上下文和底稿契约

读取 `profile.json`、简历和底稿的完整可见内容，包括正文、表格、页眉页脚、section、图片和复杂对象提示。核对文件哈希；如果用户在外部修改底稿但没有明确要求更新模板，先请求确认。

使用 `tools/docx_workbench.py inspect` 或 `snapshot` 查看底稿结构。读取初始化时保存的段落职责映射，但把它当作辅助判断；无用户模板时，默认模板包含两个独立的论文理解段落（实际为 14 个正文段落），自定义模板不能强行套用默认模板结构。

### 2. 多源调研导师

像处理正常复杂学术调研一样使用当前可用的 Codex 搜索、浏览、页面访问和文件下载能力。先确认是哪位导师，再确认单位、职称、招生方向、研究方向、研究路径、成果归属和近期重点。

主页只是参考和定位起点。根据线索继续打开学校/学院页、团队页、作者页、论文列表、学术索引、DOI/出版页、机构仓储、作者版本和其他可靠来源；不固定搜索引擎、渠道顺序或尝试次数。

遇到一个网站、域名、搜索接口或下载入口失败时，换一条有价值的路线继续查找；不要把单个工具故障扩大成全网不可用，也不要机械重复同一个失败请求。保存有效来源和失败线索，便于恢复。

### 3. 建立候选论文池并选择代表作

在写信前先从导师研究路径和公开成果中建立候选池。每条候选至少记录：

- 完整题目、完整作者、年份、期刊/会议、DOI 或其他唯一标识；
- 导师作者角色、身份置信度、同名消歧依据和稳定合作者/机构依据；
- 研究阶段、所属研究主线、代表性判断和与正文的适配说明；
- 证据等级、来源路径、全文文件路径（如有）；
- `selected`、`alternative`、`excluded` 或 `pending` 状态及取舍理由。

证据等级统一使用：

- `PDF_FULLTEXT_READ`：本地 PDF 已下载并实际阅读；
- `FULLTEXT_NON_PDF`：可靠 HTML/XML/网页全文已读取；
- `ABSTRACT_ONLY`：只有摘要或摘要级内容；
- `METADATA_ONLY`：只有题目、作者、年份、期刊、DOI 等元数据；
- `IDENTITY_UNVERIFIED`：作者或论文归属仍未确认。

代表性优先于学生经历匹配度和下载便利性。通常从核心主线、阶段变化、当前方向中选择一到两篇最值得写进正文的论文；相近代表性候选之间，全文可得性可以帮助取舍。不能因为容易下载就把边缘论文提升为代表作，也不能为了保留最重要的论文而编造未读取的细节。

如果经身份消歧和作者归属核验后的高置信度候选池不超过 3 篇，先把它当成调研不足的风险信号，主动回查遗漏的学校/学院/团队/作者/论文和全文线索，继续扩展到合理的检索饱和点。只有补充检索后仍不超过 3 篇，才能说明可能是导师成果较少或公开资料不完整，并评估研究历程画像是否足以支撑正文。不得为了凑数加入同名或归属不明成果。

检索接近饱和的依据是：已沿着当前有价值的身份、机构、成果、题名、DOI、作者和全文线索继续追踪，新增结果开始重复、无法确认归属，或不再提供新的代表性候选。不要仅因为找到两篇可下载 PDF 就停止。

### 4. 获取并阅读最终论文

先检查任务目录中已有文件和历史记录，复用有效 PDF。对选定或替代论文继续追踪正式版本、作者版本、accepted manuscript、机构仓储、实验室页面、预印本或其他可核验全文入口。

实际下载后检查文件头、题名、作者、年份、版本/DOI 和导师归属，再读取本地 PDF。HTML、登录页、错误脚本和摘要页面不能当 PDF。某篇失败时继续处理候选池中的其他代表性论文。

按 [paper-reading.md](references/paper-reading.md) 逐篇记录研究问题、方法、创新类型、实验结果、局限、证据边界和信件切入点。完整研究历程放入报告，正文只使用已经核验且适合写入的少数节点。

### 5. 审查底稿并写作

先将底稿内容拆成：可保留的通用表达、需按简历核验的个人事实、需按目标导师替换的导师事实、需按本轮论文重写的研究内容。即使没有占位符，也要检查旧姓名、学校、成绩、项目、论文、研究方向、申请目标和联系方式。

研究报告承载完整导师画像、研究路径、候选论文、证据等级、精读内容和取舍理由。自荐信正文只保留一到两个最有价值的研究节点，服从底稿已有段落职责和容量，不把完整报告塞进论文段。

### 6. 使用完整底稿生成 DOCX

必须复制底稿作为输出基础。禁止使用 `paragraph.text = ...` 或“提取所有文本后重新生成 DOCX”抹平 runs。

优先使用 `tools/docx_workbench.py replace`：

- 对占位符或短语进行跨 run 局部替换，保留占位符起始 run 的样式；
- 占位符外的文字和样式不动；
- 对确实需要整体重写的段落，使用 scoped paragraph operation，保留段落属性、段落样式和主要文字格式；
- 无法可靠映射多种局部格式时记录人工复核项，不假装完美保真；
- 表格、页眉页脚、图片、section、文本框、批注或特殊控件无法安全编辑时保持原样，不删除、扁平化或转换。

用户模板和默认模板采用相同处理规则。默认模板不是所有用户模板的母版。

正文变长时优先压缩技术细节、减少次要论文和冗余表述；不缩小字号、不改变页边距、不压缩行距、不擅自新增段落来适应内容。仍然无法自然放入时保留草稿并标记人工复核，完整内容放在研究报告。

### 7. 结构、事实和视觉 QA

使用 `snapshot` 和 `compare` 比较生成前后底稿结构。关键差异包括删除或新增 section、表格、页眉页脚、图片、文本框、关键段落、署名结构，改变页边距，段落属性变化和大范围 run 样式塌缩。文字长度、自然分页和占位符替换引起的 run 数变化记录为警告或信息，不自动判定失败。

另做事实残留检查：称呼、目标导师、学校、论文题目、作者、年份和个人事实正确；旧导师、旧论文、旧学校和明显旧个人信息没有残留；论文具体内容只来自允许的证据等级。

如果有 DOCX 渲染器，再做视觉检查；没有渲染器时明确写“视觉未验证”。结构通过不等于视觉通过。

工具无法运行时可以继续处理，但必须降低 QA 声明强度，明确“结构快照/自动比较未完成”，不能声称格式已验证。

## 状态与交付

最终使用面向用户的状态：

- **完成**：导师调研范围、论文证据、正文事实和 DOCX 结构 QA 达到交付要求；视觉检查另行注明是否完成。
- **部分完成**：已完成有价值的研究或生成需要人工复核的草稿，明确列出缺口和证据边界。
- **需要补充材料/人工复核**：关键论文全文、个人事实、复杂底稿对象或关键结构无法可靠确认。

普通网页失败、单篇论文失败或一次下载失败不应扩大为整体停止。只有在没有足够证据支撑论文特定写作、关键个人事实未确认或底稿关键结构无法可靠处理时，才停止相应交付，不用摘要或标题伪造精读内容。

完整交付通常包括：研究报告、候选论文与来源账本、逐篇论文精读、自荐信正文、目标导师 DOCX、结构比较报告、事实 QA 和恢复说明。保留源底稿、简历和默认模板不变。

## 任务恢复

任务目录至少保存 `研究报告.md`、`论文候选与来源.md`、`papers/`、必要的 `sources/`、结构快照/比较报告和 `恢复说明.md`。重新执行时先读取已有产物，复用已验证来源和 PDF，只继续未完成部分；不要因为历史记录里有一次失败就直接结束。
