# DOCX 结构、事实与视觉 QA

## 结构快照

使用 `tools/docx_workbench.py snapshot` 保存底稿和生成文件的结构摘要，至少比较：

- 正文和表格段落位置、section 数量；
- 页边距、页眉页脚、段落样式、对齐、缩进、行距；
- run 样式摘要、加粗/斜体/颜色和超链接/图片/文本框对象；
- 署名、日期和关键段落是否仍存在。

## 差异分层

关键差异包括：删除或新增表格、section、页眉页脚、图片、文本框或关键段落；改变页边距；改变段落属性；删除署名结构；多样式 run 大范围塌缩。文字长度变化、自然换行/分页、占位符替换造成的 run 数变化是警告或信息，不自动判失败。

如果用户明确要求某项格式变化，将其记录到允许差异后再比较。用户确认新的满意稿后重新生成契约。

## 事实检查

- 文件可以重新打开；
- 称呼、目标导师姓名、单位、学校/学院、论文题目、作者和年份与本轮资料一致；
- 个人姓名、学校、专业、成绩、科研职责、竞赛和奖项来自简历或用户确认；
- 旧导师、旧论文、旧学校和明显旧个人信息没有残留；
- 具体论文方法、实验和局限只来自允许的证据等级；
- 源底稿、简历和默认模板未被覆盖。
- 简历校验使用 `profile.json` 中登记的精确路径；其他同名文件不作为候选替代品。

底稿更新只影响工作区底稿和模板快照。若简历登记路径本身存在且哈希匹配，不能因为 `profile.json` 的模板字段变化、任务目录变化或其他路径出现同名简历而重新阻断任务。

## 视觉检查

有可用 DOCX 渲染器时检查分页、溢出、签名位置、裁切、重叠和异常空白。没有渲染器时记录“视觉未验证”，不能将结构通过等同于视觉通过。

## 工具不可用

工具或依赖无法运行时可以继续完成研究和写作，但最终必须明确“结构快照/自动比较未完成”，不能宣称底稿格式已验证。
