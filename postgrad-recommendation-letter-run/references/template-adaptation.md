# 底稿适配与写作

## 底稿优先级

用户上传的模板或上一轮明确确认满意的 DOCX 是完整底稿；没有用户模板时才使用内置默认 DOCX。不同底稿不强行统一成默认 13 段。

以简历和用户最新明确确认内容为事实准绳，逐段审查底稿：

- 可保留的通用表达；
- 与简历冲突或待确认的姓名、学校、专业、成绩、项目、奖项、联系方式；
- 需要替换的旧导师、旧论文、旧研究方向和旧申请目标；
- 没有占位符但已经失效的普通正文。

底稿中的事实不能因为格式完整就自动成为个人事实。

## 段落职责和研究内容

使用底稿契约中的段落映射作为辅助，结合实际全文重新确认职责。研究报告负责完整导师画像、研究路径、候选池、证据等级和论文精读；正文只挑一到两个最有价值、已经核验且适合写入的研究节点。

研究段明显比底稿长时，先压缩论文术语、实验细节和次要节点。不得靠缩小字号、改变页边距、压缩行距或无限拉长原段落解决容量问题。无法自然放入时记录人工复核。

## DOCX 编辑策略

1. 复制底稿到新输出路径。
2. 生成前调用 `tools/docx_workbench.py snapshot` 或读取初始化快照。
3. 优先用 `replace` 对占位符和短语做跨 run 局部替换。占位符起始 run 的样式作为替换内容默认样式，占位符外样式保持不变。
4. 必须整体重写时，使用带 scope 的段落操作，保留段落属性、段落样式和主要文字格式。无法可靠映射多种局部样式时记录人工复核。
5. 表格、页眉页脚、图片、section、文本框、批注和特殊控件不能安全修改时保持原样，不能扁平化或删除。
6. 另存为 `自荐信_目标导师姓名.docx`，不覆盖源文件。

禁止使用 `paragraph.text = ...` 重建整段，禁止提取全部文本后另建一个格式相似但结构不同的 DOCX。

## 文字要求

自荐信应自然回答：为什么联系这位导师，读懂了哪篇代表性论文或研究主线，自己的哪些经历可以迁移，还缺什么，研究生阶段准备如何学习。语气真诚、谦逊、正式，避免空泛赞美、机械翻译摘要、过度承诺和无证据匹配。

论文段只能使用允许证据支撑的内容。不要把学生写成已经掌握导师论文中的方法，也不要把仿真自动写成实体部署。
